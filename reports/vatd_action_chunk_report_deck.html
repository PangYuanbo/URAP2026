problem

微小无人机检测的难点

  • 目标常常只有 几个像素，单帧外观和鸟、虫、噪点、压缩伪影几乎不可分。
  • 载机自身运动 (ego-motion) 让背景也在动，运动 ≠ 目标。
  • 评测协议（AOT）重罚误报：FAR / FPPI / EDR@300。提高召回很容易，但会同时拉高误报。
  • 约束：重训练（RTX 5090）、轻推理（机载）。

core idea

借鉴机器人 VLA 的「动作分块」

核心赌注：无人机的运动方式本身就是判别特征。一段弱轨迹是不是无人机，用它动起来像不像来打分，而不只看每帧外观。

🤖 机器人 VLA (Octo / ACT)

观测视频 → 一次预测未来一小段 action chunk（H 步动作），让动作连贯、抗噪。

机器人轨迹 → [关节/末端位移序列]

🛸 本项目 VATD

无人机视频 episode → 预测候选框未来一小段的 bbox 运动分块。

无人机 tube → [Δ框 位移序列]

关键澄清：这里砍掉了 Language 分支 → 严格说是 VA（Vision-Action），不是 VLA。命名 VATD = Video-Action Tiny Drone Detector，论文定位为「一个独立的视觉-动作 Transformer」，不是「TransVisDrone + action chunk」。

representation

什么是一个 action chunk

qstr_dronedet/tracking/action_chunk.py
# 一帧的动作 = 中心位移 + 尺度的对数变化
action_t = [ dx, dy, dlog_w, dlog_h ]
  dx,dy   = next.cx-prev.cx, next.cy-prev.cy
  dlog_w  = log(next.w / prev.w)   # 乘性→取对数, 对称好回归
  dlog_h  = log(next.h / prev.h)   # clip 到 ±6 防尺度爆炸

# 一个样本: 用过去 N 帧预测未来 H 帧
chunk = action_{t+1 : t+H}      # ← 这就是 action chunk

Octo-style 统一样本格式

统一 tube episode
{ dataset_source, seq, track_id, anchor_frame,
  past_boxes[N,4], past_scores[N], past_visible[N],
  future_actions[H,4], future_boxes[H,4],
  label, bucket }   # 1=类无人机 / 0=背景

归一化铁律：多数据集必须逐行用 image_w/h 归一化到统一坐标系。像素坐标会让 NPS/AOT/ARD100 动力学不可比，正是这点曾让学习策略打不过简单匀速。

design correction

最重要的一个设计修正

❌ 一开始想错

action chunk 当第一级检测器

「预测下一个框 → 当成检测结果」。

微小框上几像素误差就让纯坐标预测崩掉，而且回答不了「这段里到底有没有无人机」。

✅ 修正后

action chunk 当动力学打分器

不做检测，而是给一条弱候选 tube 打分：物理上、视觉上像不像无人机。

即 track-before-detect：先连轨迹假设，再用动力学+证据决定是否接受。

实验发现（2026-06-04）：匀速 (constant velocity) 是个意外地强的短时程基线。直接回归动作打不过匀速；改成预测 future_actions − 匀速动作 的残差策略后明显变好、几乎追平匀速 → 应当把匀速当显式基线，只学其上的残差/似然，而非黑盒替换。

evidence · AOT part0

为什么不能只靠运动平滑

TVD 预训练 AOT part0 推理 + 不同时序/匀速门限。匀速门限确实压低误报，但也同时砸掉 encounter 召回：

变体（同一检测输出）HFAR ↓AFDR range ↑Detection enc.@300
TVD + IoU track @0.2066990.8839 / 10
+ gap2 len≥214640.6566 / 10
+ gap2 len≥3 + CV≥0.754830.4374 / 10
+ gap2 len≥3 + CV≥0.931450.0761 / 6

读法：硬性匀速门限把 HFAR 从 1464 → 145，但 encounter 也从 6/10 掉到 1/6，AFDR 几乎归零。

目标：不是「更长的轨迹」，而是学一个判别 UAV 式动力学的打分器，在 0.55–0.80 误报工作点附近把召回拉回来。

pipeline · Route B

动作分块怎么接进系统

① 低阈值过检YOLOMG/TVD/YOLO-P2 低阈值，保留平时被滤掉的弱候选
③ Action-chunk 动力学打分 ★tube→归一化 chunk→VATD→类无人机运动分 + 残差一致性
② 构造候选 tube宽松门限连成短 tube；复用 track_id 大间隔处必须按 gap 切断
④ 证据整合 → 逐帧检测检测证据 + 动力学似然 + 形状稳定 + 低背景概率 一致才接受

已实现的打分模式

scorer modes
learned_consistency = exp(-learned_error / scale)               # 残差误差越小越像
cv_consistency      = exp(-constant_velocity_error / scale)     # 匀速基线
improvement         = sigmoid((cv_error - learned_error)/scale) # 学习比匀速好多少
hybrid              = learned_consistency * improvement

latest · ego-adaptive

最新一代在解决什么

痛点：剧烈 ego-motion 会污染观测到的「动作」——目标没动，但相机动了框也在动。

① 相机特征条件化

从行里取 camera_dx/dy, camera_speed, warp_error, camera_motion_quality 组成 ego 向量，注入每个 readout token。

② 多时程 + 软路由

维护 horizons=(3,5,7)，每个一对 (motion/action) 头；router 用 ego 算 softmax 权重软加权融合。相机稳→长时程，相机抖→短时程。

EgoAdaptiveVATDTransformer.forward
encoded  = encoder(visual + state + pos)
router_w = softmax(router(ego_features))  # ego 决定权重
for h in (3,5,7):
    token = encoded[:, -h:].mean(1) + motion + ego
    m_h, a_h = motion_head_h(token), action_head_h(token)
motion_logits   = Σ router_w · m_h    # 类无人机运动分
action_residual = Σ router_w · a_h    # 残差动作

数据集还按 ego 不稳定度降低动作监督权重：target_action_weight = clip(1 − ego_instability, 0.15, 1.0)

evaluation discipline

怎样才算「赢」

tracklet 级好看的数字 ≠ 论文结果。必须一路打回帧级、过官方评测器：

tracklet 级

联合分类器 best_f1。只能和同协议 tracklet 基线比，不能当 NPS mAP / AOT HFAR。

帧级代理

贴回逐帧预测，用本仓库 GT-CSV/IoU 协议算 P/R/F1，工程选阈值用。

官方评测器

NPS: AP@0.5 · AOT: HFAR/FPPI/EDR@300，同 split、同工作点对比 TVD。

赢的判据：在相同或更低的误报 (FPPI/FAR) 预算下，召回 / encounter 高于 TransVisDrone（尤其微小、弱运动目标）。光提原始召回不算赢；claim_gate.status = pass 要求至少一个固定预算下的召回 win。

summary · Q&A

一句话总结

VATD 把机器人 VLA 的 action chunk 借过来——砍掉语言，并把它从「预测下一个框的检测器」改造成「判断一段弱轨迹动起来像不像无人机的动力学打分器」。最新的 EgoAdaptiveVATD 用相机运动做条件化与多时程软路由，专治载机抖动污染轨迹。

运动 = 第三类判别信号 track-before-detect 相同误报预算下提召回
