problem

Why tiny-drone detection is hard

  • Targets are often just a few pixels — single-frame appearance is nearly indistinguishable from birds, insects, specks, compression artifacts.
  • The host platform's own motion (ego-motion) makes the background move too: motion ≠ target.
  • The evaluation protocol (AOT) heavily penalizes false alarms: FAR / FPPI / EDR@300. Raising recall is easy but inflates false alarms.
  • Constraint: heavy training (RTX 5090), lightweight onboard inference.

VATD = a new third signal: motion / action.

core idea

Borrowing the "action chunk" from robot VLA

The core bet: a drone's way of moving is itself a discriminative feature. Whether a weak tracklet is a drone is scored by how drone-like its motion is, not only by per-frame appearance.

🤖 Robot VLA (Octo / ACT)

Observe video → predict a short future action chunk (H steps at once) for coherent, noise-robust action.

robot trajectory → [joint/end-effector deltas]

🛸 This project: VATD

Drone video episode → predict the candidate box's short future bbox motion chunk.

drone tube → [Δbox deltas]

Key clarification: the Language branch is dropped → strictly this is VA (Vision-Action), not VLA. Named VATD = Video-Action Tiny Drone Detector, positioned in the paper as "an independent vision-action Transformer", not "TransVisDrone + action chunk".

representation

What an action chunk is

qstr_dronedet/tracking/action_chunk.py
# one-frame action = center shift + log scale change
action_t = [ dx, dy, dlog_w, dlog_h ]
  dx,dy   = next.cx-prev.cx, next.cy-prev.cy
  dlog_w  = log(next.w / prev.w)   # multiplicative→log, symmetric
  dlog_h  = log(next.h / prev.h)   # clip to ±6 to stop blow-ups

# one sample: use past N frames to predict next H frames
chunk = action_{t+1 : t+H}      # ← this is the action chunk

Octo-style unified sample format

unified tube episode
{ dataset_source, seq, track_id, anchor_frame,
  past_boxes[N,4], past_scores[N], past_visible[N],
  future_actions[H,4], future_boxes[H,4],
  label, bucket }   # 1=drone-like / 0=background

Normalization rule: across datasets, boxes must be normalized per-row by image_w/h to a shared coordinate system. Pixel coordinates make NPS/AOT/ARD100 dynamics incomparable — exactly what once made learned policies lose to plain constant velocity.

design correction

The single most important design fix

❌ The early mistake

action chunk as a first-stage detector

"Predict the next box → call it a detection."

A few-pixel error on a tiny box collapses pure coordinate prediction, and it can't answer "is there a drone in this clip at all".

✅ The fix

action chunk as a dynamics scorer

Not detection — score a weak candidate tube: is it physically and visually drone-like?

i.e. track-before-detect: form tracklet hypotheses first, then accept by dynamics + evidence.

Empirical finding (2026-06-04): constant velocity (CV) is a surprisingly strong short-horizon baseline. Direct action regression lost to CV; switching to a residual policy that predicts future_actions − CV_actions was clearly better and nearly matched CV → keep CV as an explicit baseline and only learn the residual / likelihood, rather than replacing it with a black box.

Goal: not "longer tracks", but a scorer that learns UAV-like dynamics to recover recall near the 0.55–0.80 false-alarm operating point.

pipeline · Route B

How action chunks plug into the system

① Low-threshold over-detectYOLOMG/TVD/YOLO-P2 at low threshold, keep weak candidates normally filtered out
③ Action-chunk dynamics scoring ★tube→normalized chunk→VATD→drone-like-motion score + residual consistency
② Build candidate tubesloose gates link short tubes; reused track_ids must be cut at large gaps
④ Integrate evidence → detectionsaccept only when detection + dynamics + shape stability + low-background agree

Implemented scoring modes

scorer modes
learned_consistency = exp(-learned_error / scale)               # smaller residual = more drone-like
cv_consistency      = exp(-constant_velocity_error / scale)     # CV baseline
improvement         = sigmoid((cv_error - learned_error)/scale) # how much better than CV
hybrid              = learned_consistency * improvement
architecture

Four generations of the model

All in qstr_dronedet/tracking/video_action_policy.py, evolving from "plain action regression" to a "camera-adaptive motion-action scorer".

gen 1

VideoActionChunkTransformer

crop+state→Transformer, single head regresses future_actions. Validates the pipeline runs.

gen 2

VideoActionMultiHead

Adds a classification head: action regression + is-it-drone-like. Action becomes a discriminative signal.

gen 3

VATDMotionActionTransformer

The real VATD. Main head motion_action (BCE) + auxiliary action_residual (SmoothL1). Emits vatd_score.

gen 4 · current

EgoAdaptiveVATDTransformer ★

Camera-conditioned + multi-horizon soft adaptation (latest git commits).

latest · ego-adaptive

What the latest generation solves

Pain point: heavy ego-motion contaminates the observed "action" — the target hasn't moved, but the box moves because the camera did.

① Camera-feature conditioning

Build an ego vector from camera_dx/dy, camera_speed, warp_error, camera_motion_quality and inject it into every readout token.

② Multi-horizon + soft router

Maintain horizons=(3,5,7), each with a (motion/action) head pair; a router uses ego features to compute softmax weights that softly fuse them. Steady camera→long horizon, shaky→short.

EgoAdaptiveVATDTransformer.forward
encoded  = encoder(visual + state + pos)
router_w = softmax(router(ego_features))  # ego sets the weights
for h in (3,5,7):
    token = encoded[:, -h:].mean(1) + motion + ego
    m_h, a_h = motion_head_h(token), action_head_h(token)
motion_logits   = Σ router_w · m_h    # drone-like-motion score
action_residual = Σ router_w · a_h    # residual action

The dataset also down-weights action supervision by ego instability: target_action_weight = clip(1 − ego_instability, 0.15, 1.0)

evaluation discipline

What counts as a "win"

Pretty tracklet-level numbers ≠ a paper result. Everything must be carried back to frame level through an official evaluator:

tracklet level

Joint-classifier best_f1. Comparable only to same-protocol tracklet baselines, not NPS mAP / AOT HFAR.

frame-level proxy

Apply back to per-frame predictions, P/R/F1 via this repo's GT-CSV/IoU protocol, for threshold selection.

official evaluator

NPS: AP@0.5 · AOT: HFAR/FPPI/EDR@300, same split & operating point vs TVD.

Win criterion: at the same or lower false-alarm (FPPI/FAR) budget, recall / encounters exceed TransVisDrone (especially for tiny, weak-motion targets). Raw recall alone doesn't count; claim_gate.status = pass requires at least one fixed-budget recall win.

The honest caveat: the gain comes from soft rescoring, not a hard action filter — a hard filter collapses recall (AFDR ≈ 0.535). It is still "TVD proposals + Octo-like action model + soft fusion", not yet a fully end-to-end VLA detector. For contrast, a gap-insert variant worsened FAR to 94.88, so the paper mainline is action/VLA-style video-dynamics rescoring — not gap insert.

summary · Q&A

VATD borrows the robot VLA action chunk idea — drops language and reshapes it from "a detector that predicts the next box" into "a dynamics scorer that judges whether a weak tracklet moves like a drone". The latest EgoAdaptiveVATD adds camera-motion conditioning and multi-horizon soft routing to fight host-platform shake contaminating tracklets.
