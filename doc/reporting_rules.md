# 教授汇报 MD 写作规则（本仓库约定）

目的：给教授的版本以“结论与可复算证据”为主，不混入过多工程细节；工程细节放在各 `repro_*.md`/脚本与日志里。

## 1) 默认不写入教授汇报的内容（已按你的删改理解记录）

| 内容类型 | 教授汇报是否默认包含 | 原因 | 放在哪（替代入口） |
|---|---|---|---|
| 磁盘占用/下载体积/硬盘清理细节 | 否 | 过于运维化，非科研重点 | `tools/size_report.py`；（需要时再单独生成一次快照） |
| OS 进程监控（PID、GPU util、log tail 等） | 否 | 过于过程化，教授通常只关心结果与可复现入口 | `tools/monitor_*.ps1`；`artifacts/logs/*` |
| Windows/PyTorch 兼容性补丁逐条清单 | 否 | 对教授汇报价值低，且会拉长文档 | `doc/repro_transvisdrone.md`；`doc/repro_esod.md`；`doc/repro_edtc.md` |
| 长段命令行原始输出 | 否 | 信息密度低、难读 | 只在 `repro_*.md` 中保留关键命令与关键输出（指标/路径） |
| 过长的 next steps 分解（工程排期） | 否（仅保留 3-5 条要点） | 容易喧宾夺主 | 在教授汇报中只留“下一步方向”；详细排期放内部任务文档 |

## 2) 教授汇报建议结构（最小集合）

| 章节 | 必需 | 推荐形式 |
|---|---|---|
| Reference（术语对照） | 是 | 1 张表：TransVisDrone/AOT/NPS/Winner 的定义与入口 |
| NPS provenance（同名数据集多标注源） | 是 | 1 张表：TVD 标注（Dogfight） vs Li-TETC 标注（time_layer）差异 + 本地路径 |
| 结论速览 | 是 | 1 张表：每条主线 1 行（状态 + 证据路径） |
| 仓库与论文/代码对应关系 | 是 | 1 张表：repo/paper/commit/状态 |
| 核心实验结果 | 是 | 1-2 张表：NPS 指标 + AOT 官方指标 |
| 时间线 | 可选 | 1 张表：按日期列出关键 milestone |
