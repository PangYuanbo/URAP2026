VATD · Action-Chunk 思路讲解

把机器人 VLA 的「动作分块 (action chunk)」搬到微小无人机检测里 —— 用「运动/动作」当识别信号

0先把它放回整个框架里

这个仓库主线是 QSTR-DroneDet：一个质量感知的两阶段微小无人机检测框架。它故意把「候选生成」和「识别」拆开，方便诊断一次漏检到底是哪一环坏了。

Stage A · 候选生成 (over-detect)
YOLO-P2 / 运动候选 / tracker 候选 / 可选 fallback 检测器 —— 低阈值，只要召回不要精度
↓
Stage B · 识别 (recognize)
图像 crop + 特征 ROI + 时序 tube + 运动/对齐元数据 → 判类别 + drone 置信度
↓
融合 + 质量日志
规则/MLP 融合；用 q_H/对齐质量防止坏单应性或剧烈 ego-motion 主导结果

VATD 是新加入的第三类信号。前面的 Stage A/B 主要看「单帧长什么样」。微小无人机往往只有几个像素，单帧证据极弱，很容易和鸟、虫、噪点、压缩伪影混淆。VATD 的核心赌注是：

无人机的「运动方式 (dynamics)」本身就是一个判别特征。 一段弱候选轨迹是不是无人机，可以用它「动起来像不像无人机」来打分，而不只看每一帧的外观。

1为什么叫「VLA 的 action chunk」？

灵感来自机器人学里的 Octo / ACT 类 VLA（Vision-Language-Action）模型。那类模型的范式是：

🤖 机器人 VLA

观测视频 → 预测未来一小段动作分块（action chunk，一次预测 H 步而不是 1 步），让动作连贯、抗噪。

机器人轨迹 → action chunk = [关节/末端位移序列]

🛸 本项目 VATD

无人机视频 episode → 预测候选框未来一小段的bbox 运动分块。机器人的 action chunk 在这里变成短时程的「框运动序列」。

无人机 tube → action chunk = [Δ框 位移序列]

关键澄清（来自设计文档）：这里砍掉了 Language 分支，所以严格说它是 VA（Vision-Action），不是 VLA。命名 VATD = Video-Action Tiny Drone Detector。论文定位是「一个独立的视觉-动作 Transformer」，不要描述成「TransVisDrone + action chunk」或「YOLOMG + action chunk」——已有检测器只是早期训练时的可选候选来源。

2什么是一个 action chunk？（核心数据表示）

实现在 qstr_dronedet/tracking/action_chunk.py。一条轨迹的每个框先归一化成 cxcywh，相邻两帧之间的变化定义为一个 action：

# box_action(prev, next)  —— 一帧的动作 = 中心位移 + 尺度的对数变化
action_t = [ dx,  dy,  dlog_w,  dlog_h ]
         =  next.cx-prev.cx,  next.cy-prev.cy,  log(next.w/prev.w),  log(next.h/prev.h)

# 一个样本（窗口）：用过去 N 帧，预测未来 H 帧的动作分块
chunk = action_{t+1 : t+H}        # 这就是 "action chunk"

为什么用 dlog_w / dlog_h 而不是直接 dw/dh？因为尺度变化是乘性的，取对数后才对称、好回归，且 apply_box_action 里会把它 clip 在 ±6 防止微小框上一点点像素误差炸成巨大尺度跳变。

统一的多数据集样本格式（Octo-style）

Octo 的精神是「把很多数据集归一化成同一种样本格式」。这里的统一样本不是机器人 episode，而是「无人机 tube episode」：

{
  dataset_source, seq, track_id, anchor_frame, # 身份/来源
  past_boxes [N,4],  past_scores [N],  past_visible [N],   # 条件 = 过去
  future_actions [H,4],  future_boxes [H,4],                # 目标 = 未来
  label,  bucket    # 1=类无人机正样本 / 0=背景；bucket 如 hard_tiny_positive
}

归一化铁律：多数据集必须用逐行 image_width/height 归一化到统一坐标系。像素坐标会让 NPS / AOT / ARD100 的动力学不可比，sanity 测试里就是这点导致学习策略打不过简单的匀速基线。

3最重要的一个设计修正

❌ 一开始想错的做法

把 action chunk 当成第一级检测器：「预测下一个框 → 就把它当检测结果」。

在微小框上几个像素的误差就让纯坐标预测崩掉，而且它根本回答不了「这段里到底有没有无人机」。

✅ 修正后的做法

action chunk 不做检测，而是建模无人机动力学，给一条弱候选 tube 打分：它在物理上、视觉上像不像无人机。

即 track-before-detect：先连成轨迹假设，再用动力学+证据决定是否接受。

匀速 (Constant Velocity) 是一个出乎意料强的基线

2026-06-04 的 sanity 实验发现：

  • 直接回归未来动作 打不过匀速外推（即使做了逐行归一化）。
  • 改成残差策略——预测 future_actions − 匀速动作——明显更好，几乎追平匀速。
  • 所以模型应当把匀速当显式基线，只学它之上的残差/似然，而不是用黑盒策略整个替换掉匀速。
但动力学单独也不够。 真实低置信度 smoke 里，光靠运动平滑度，一个平滑的背景假阳竟然排在真目标前面（0.85 vs 0.64）。结论：运动平滑是必要非充分。production 打分必须是联合分：检测证据 + 动力学证据 + 反背景证据 + 轨迹几何。

4Route B 流水线：动作分块怎么接进系统

① 低阈值过检
YOLOMG / TVD / YOLO-P2 低阈值跑，保留平时会被滤掉的弱候选 → frame_id, bbox, objectness, source
↓
② 构造候选 tube
宽松门限把邻近弱检测连成短 tube（只是假设生成器，不是最终 tracker）。注意：复用的 track_id 出现大帧间隔时必须按 gap 切断，否则 action chunk 非法
↓
③ Action-chunk 动力学打分 ★
把 tube 转成归一化 action chunk，过 VATD 模型，得到「类无人机运动」分数 + 残差一致性
↓
④ 证据整合 → 逐帧检测
检测证据 + 动力学似然 + 形状/尺度稳定性 + 低背景概率 一致才接受

已实现的几种打分模式

learned_consistency = exp(-learned_error / scale)              # 学到的残差误差越小越像
cv_consistency      = exp(-constant_velocity_error / scale)    # 匀速基线一致性
improvement         = sigmoid((cv_error - learned_error)/scale)# 学习比匀速好多少
hybrid              = learned_consistency * improvement

scale 必须用归一化坐标，不能用像素尺度——这是多数据集打分的前提。

5模型架构的演化（代码里真实存在的四代）

都在 qstr_dronedet/tracking/video_action_policy.py 里。逐步从「单纯回归动作」走到「相机自适应、多时程的运动-动作打分器」：

VideoActionChunkTransformer
最早。crop+state 过 Transformer，单头只回归 future_actions。SmoothL1 损失。验证「视频→动作」管线能跑。
VideoActionMultiHead
加一个分类头：同时输出 动作回归 + 是否类无人机。开始把「动作」当判别信号而非纯预测。
VATDMotionActionTransformer
正式 VATD。主头 motion_action_head（BCE，判类无人机运动）+ 辅助 action_residual_head（学相对匀速的残差）。输出 vatd_score。
EgoAdaptiveVATDTransformer ★
最新（git 头几个 commit）。相机条件化 + 多时程软自适应。下面细讲。

最新一代：EgoAdaptiveVATD 在做什么

它解决的痛点是：剧烈 ego-motion（载机自身抖动/快速运动）会污染观测到的「动作」——目标没动，但因为相机动，框也在动。于是这一代做了两件事：

① Ego（相机）特征条件化

从行里提取 camera_dx/dy、camera_speed、warp_error、camera_motion_quality 等组成 ego 特征向量，单独编码后注入每个 readout token。模型「知道」当前相机有多稳。

② 多时程 + 软路由 (router)

同时维护几个时程 horizons=(3,5,7)，每个 horizon 一对 (motion 头, action 头)。一个 router 用 ego 特征算 softmax 权重，把各 horizon 的输出软加权融合。相机稳→可信长时程，相机抖→偏短时程。

# EgoAdaptiveVATDTransformer.forward 的核心（简化）
encoded   = encoder(visual + state(state) + pos)          # 时序 Transformer
router_w  = softmax(router(ego_motion_features))           # [B, num_horizons]  ← ego 决定权重
for h in horizons (3,5,7):
    token = encoded[:, -h:, :].mean(1) + motion_embed + ego_embed
    motion_logits_h, action_residual_h  = motion_head_h(token), action_head_h(token)
motion_logits   = Σ router_w · motion_logits_h             # 软加权 → 类无人机运动分
action_residual = Σ router_w · action_residual_h           # 软加权 → 残差动作（相对匀速）

另外数据集里还根据 ego 不稳定度动态降低动作监督权重：target_action_weight = clip(1 − ego_instability, 0.15, 1.0)——相机越抖，越不信「未来动作」这个回归目标，避免被相机抖动带偏。

6训练目标与输出

损失（MVP）

L = L_motion_action            # 主：BCE，类无人机 vs 非
  + λ · L_action_residual      # 辅：SmoothL1，残差动作

完整检测器版还会加 L_detection。主任务是分类，残差动作只当「动力学先验」辅助，不是主任务。

打分输出字段

motion_action_score          # 类无人机运动概率
vatd_action_consistency_score

第一次消融的最简融合：final = base_detector_score × motion_action_score

7评测纪律（为什么流水线这么长）

仓库对「能不能写进论文」卡得很死。tracklet 级别的好看数字不等于论文级结果，必须一路打回到帧级、过官方评测器：

tracklet 级
联合分类器 best_f1 —— 只能和同协议的 tracklet 基线比，不能当成 NPS mAP / AOT HFAR
↓
帧级代理
把学到的打分器贴回逐帧预测，用本仓库 GT-CSV/IoU 协议算 P/R/F1（工程选阈值用）
↓
官方评测器
NPS: AP@0.5 / R · AOT: HFAR/FPPI/EDR@300 —— 同 split、同 FPPI/FAR 工作点对比 TransVisDrone，才是论文 claim
赢的判据：在相同或更低的误报 (FPPI/FAR) 预算下，召回/encounter 高于 TransVisDrone（尤其对微小、弱运动目标）。光提原始召回不算赢。claim_gate.status=pass 要求至少有一个固定预算下的召回 win。

8一句话总结

VATD 把机器人 VLA 的 action chunk 思想借过来——但砍掉语言、并把它从「预测下一个框的检测器」改造成「判断一段弱轨迹动起来像不像无人机的动力学打分器」。最新的 EgoAdaptiveVATD 进一步用相机运动特征做条件化和多时程软路由，专治载机抖动污染轨迹的问题。它是 track-before-detect 框架里和检测证据、反背景证据并列的第三类（运动）信号，最终要在相同误报预算下，对微小弱目标把召回做得比 TransVisDrone 高。
